# MirasAI 0.10.0

This release changes the Joomla translation write contract. Calls that previously
created articles immediately now return a preview by default. Update callers
before upgrading a Joomla host; refresh cached schemas with `mcp2cli --refresh`.

## Joomla caller migration

1. Read the source with `content/read` and prepare translated text. For Builder
   layouts, use `yootheme_translatable_nodes[].replacement_key`.
2. Call `content/translate` with all intended arguments and `dry_run=true`.
3. Review the destination, state, alias, category, menu, parity warnings and
   fallback requirement. Copy the returned `etag`.
4. Repeat the identical arguments with `dry_run=false`, that token as `if_match`,
   and `confirm_guarded_write=true`. A token from `content/read` is not a
   translation preview token. Changed arguments or content require a new preview.

This example is a preview request; replace the IDs with an actual source and a
compatible target category:

```json
{
  "source_id": 123,
  "target_language": "es-ES",
  "target_category_id": 8,
  "translated_title": "Servicios",
  "translated_introtext": "<p>Servicios de la empresa.</p>",
  "dry_run": true
}
```

For apply, change `dry_run` to `false` and add `if_match` and
`confirm_guarded_write`. Standard articles with nonempty source fulltext also
require `translated_fulltext`; explicitly supplied empty text and `"0"` remain
those values, rather than copying the source.

- New articles default to `state=0`. Updates preserve the existing state and
  alias when omitted. New copies preserve editorial dates, author, access and
  publication schedule. Explicit publication requires verified fallback and
  editorial parity.
- Use `target_id` plus `overwrite=true` to reconcile a known unassociated target.
  Conflicting associations are rejected; groups are not merged implicitly.
- Menus are untouched by default. Select `create_menu=true` or `menu_id`, never
  both. Use `source_menu_id` when needed to resolve ambiguity. Existing menu IDs,
  aliases, access and structure are preserved; an alias collision is not proof
  that a menu is orphaned. `translated_page_title` requires a menu operation.
- `content/translate-batch` accepts 1–25 distinct source articles. Each result
  contains its own preview `etag`; send each as that item's `if_match` on apply.
  Top-level `dry_run=false` and `confirm_guarded_write=true` are also required.
  Inspect every result and retain IDs from partial failures. `fix_links=true`
  is rejected; omission or legacy `false` is accepted.
- `content/check-links` reports by default. Apply requires one `article_id`,
  `fix=true`, `dry_run=false`, its preview `if_match` and confirmation. It rewrites
  supported local numeric Joomla article links, preserving query parameters,
  HTML escaping and fragments, then saves the layout and verified fallback with
  a final compare-and-swap. SEF and absolute URLs require separate review.

The translation writer uses row locks and a per-source MySQL lock. Joomla's
nested-set Table operations can commit implicitly, so a rollback request does
not prove that all effects were undone. An error retains known IDs, attempted
effects and the article's existence after failure. Read and reconcile those
records before retrying; resume the known target instead of creating another.
The lock serializes this route's writers, not unrelated editors.

## Shared YOOtheme editorial validation

Both hosts use explicit editorial fields, including short labels, `image_alt`,
`link_aria_label` and `home_text`. Unknown text-like properties and implicit
breadcrumb labels appear as coverage warnings. CSS, configuration, bound static
values and technical query names are excluded. Disabled nodes retain their
disabled context in the manifest.

Replacement maps and complete translated layouts share the same validation:
structural HTML, technical attributes, URLs, IDs and placeholders must remain
unchanged. Textual HTML attributes such as `alt` and `aria-label` can be
translated. This reduces the old heuristic coverage; review warnings rather
than attempting to write unknown properties through a translation call.
Validation checks fidelity, not translation quality or HTML sanitization.

## WordPress and WPML

Existing target slugs are preserved when `translated_slug` is omitted. Translation
responses resolve the target permalink under its WPML language and restore the
previous language afterward; WPML could otherwise return the source article URL.
WordPress retains its own write contract: new translations are drafts and
updates preserve the target status. The Joomla preview-token migration above
does not change WordPress's input schema.

## Rendering and verified coverage

The Joomla host renders static Builder fallback in-process, including requests
through the API. It temporarily uses Joomla's site application for YOOtheme
bootstrap/render and restores the original application afterward. Batch calls
work with both cold and already-loaded Builder services. No root-level
`regenerate-introtext.php` deployment is required.

Dynamic fallback requires the target-language site runtime and appropriate
content context. The API path cannot establish that context: a draft may return
`status=partial`, while publication is rejected. Custom fields are inventoried
and flagged for review, not copied or translated automatically. Missing source
SEO metadata translations also produce parity warnings. `action=created` or
`updated` alone is not proof of `status=complete`.

Validation includes the full local suite, 127 new regression assertions, private
CLI pilots on Joomla 6.1.3 and WordPress 7.1 with WPML/YOOtheme 5.0.43, and a
package/HTTP pilot on an isolated Joomla 5.4.5, MySQL 8.4 and YOOtheme 5.0.40 clone.
The client plugins were not replaced during these pilots. See the
[validation summary](./0.10.0-validation.md) for the exact artifact hashes and
verified coverage. Operational inventories and backup locations remain local.

Not all dynamic providers or real workflow failure phases have been tested.
The module pilot reproduces a partial-persistence failure mode; it does not
identify the original reported client exception or add a module translation route.
The standalone regeneration helper's CAS has not been tested with concurrent
database connections; the host link-repair CAS has.

The local router remains the only Style compiler. These host changes render
Builder content; they do not compile LESS or regenerate Style CSS.
