# MirasAI 0.10.2

This patch fixes the WordPress plugin's self-updater. Joomla and the local router
change only in version number.

- A new release is no longer hidden for up to 6 hours. The updater cached the
  GitHub feed for 6 hours and neither "Check again" in Dashboard > Updates nor
  deleting the `update_plugins` transient (for example
  `wp transient delete update_plugins --network`) cleared it. Both now drop the
  feed cache, and its lifetime is 1 hour. On a site running 0.10.1 the 0.10.1
  release was not offered and had to be installed from the ZIP by hand.
- The release ZIP is now checked against the `sha256` published in
  `updates/mirasai-wp.json`. The updater downloads its own package itself and
  refuses the update when the hash does not match or the feed has no valid hash.
  Packages of other plugins are left untouched.

Sites on 0.10.1 still run the old updater until they reach 0.10.2. If the offer
does not appear, delete the `mirasai_wp_update_feed` site transient once, or
install the ZIP from the release.

The YOOtheme builder findings register also gains entries F-022 to F-035.

## Validation

The full local suite passes, including the new
`docker/test-wp-update-feed.php`. It covers the forced check that bypasses the
cache, the transient deletion hook, a matching package, a mismatched package,
a missing checksum and a foreign package that must be left alone. The end-to-end
update on a live WordPress site is verified after publication.
