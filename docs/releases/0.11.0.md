# MirasAI 0.11.0

Eines perquè un agent comprovi el que ha escrit, creï plantilles de YOOtheme i
deixi rastre al registre del CMS. Ve de la comparació amb MCP for YOOtheme Pro
(WootsUp) i d'un cas real; el raonament i totes les proves són a la
[proposta](../wootsup-comparison-proposal-2026-11-09.md). Res del que ja hi
havia deixa de funcionar.

Totes les eines noves són del host: les tenen el host per HTTP, mcp2cli apuntat
al host i el router, que les passa tal qual. Cap compila Style.

## Comprovar el que veu el visitant

**`site/public-fetch`** (lectura) obre una URL del mateix web sense sessió i
torna l'estat, les redireccions, el títol, `noindex`, les capçaleres de
memòria cau i un extracte. Amb `expect` diu si hi és cada text (fins a 10) i a
quina zona: capçalera, menú, contingut, peu. `cache_bust=true` afegeix un
paràmetre perquè la majoria de memòries cau de pàgina no responguin.

Només fa peticions al host del web, i valida cada redirecció amb la mateixa
regla. A Joomla sense `live_site`, el host surt de la capçalera `Host`; per
això la connexió es fixa a l'adreça que ha rebut la petició
(`CURLOPT_CONNECT_TO`) i es rebutja un `Host` amb un port no estàndard o una IP
aliena (`site_url_untrusted`). Si un web en necessita un, cal posar
`live_site`.

**`site/cache-purge`** (`safe_write`) buida les memòries cau de pàgina:

- WordPress: WP Rocket, IONOS Performance i la memòria cau d'objectes, com el
  botó de cada connector. Un `advanced-cache.php` desconegut torna
  `state=unknown`.
- Joomla: tots els grups, com «Esborra-ho tot», memòria cau de pàgina del nucli
  inclosa. La memòria cau de pàgina de JCH Optimize té emmagatzematge propi: surt
  a `unsupported` i torna `state=unknown`.

Cap dels dos buida un CDN. `dry_run=true` només llista el que buidaria.

**`template/render-check`** (lectura) renderitza un layout desat com a visitant
i diu, per path, quins elements mostren text i quins no es mostren (desactivats,
condicions, fonts buides). Les plantilles es renderitzen amb una entrada o un
article de context (`context_id`), perquè les fonts dinàmiques es resolguin. No
mira l'estat de publicació. A Joomla, YOOtheme no arrenca a l'aplicació API:
l'eina el carrega com ho fa el web públic.

## Plantilles i auditoria

**`template/create`** (`guarded_write`) crea una plantilla de YOOtheme
**desactivada**, amb nom, tipus i, si cal, un layout inicial, protegida amb el
`collection_etag` de `template/list`. Torna la clau i l'ETag per omplir-la amb
`template/element-add`. Activar-la és cosa d'una persona al Builder.

**`template/audit`** (lectura) revisa un layout desat: fitxers d'imatge que no
existeixen i llistes sense ítems (error); sense h1, h1 repetit i salts de nivell
(warning); imatges sense text alternatiu i títols de més de 70 caràcters
(notice). Cada troballa porta el path i una proposta. No jutja valors de fonts
dinàmiques.

## Escriptures més segures

- **`preview_token`:** cada dry-run d'una eina `guarded_write` el torna. Si la
  confirmació el torna i els arguments no són els mateixos, es rebutja amb
  `preview_mismatch` abans d'executar res. És opcional: qui no l'envia funciona
  com abans. El playbook diu als agents que l'enviïn.
- **`template/element-source-set`** torna `warnings: [binding_on_list_container]`
  quan es lliga una font al contenidor d'una llista (grid, slideshow…):
  YOOtheme repeteix l'ítem, no el contenidor. No rebutja res.

## Registre d'activitat

Cada escriptura feta per MCP (ni lectures, ni dry-run, ni errors) deixa una
entrada amb l'eina, el destí (`key`, `post_id`, `path`…), el client i els ETags
curts. Mai el contingut dels arguments.

- WordPress: Simple History, si està actiu. Simple History 5.36 ja marca
  l'entrada com a feta per una IA.
- Joomla: Usuaris → Registre d'accions, amb el Super User del token.
- Router: envia el `clientInfo` de l'`initialize` com a `X-MCP-Client`. Sense
  router, el host fa servir el User-Agent.

## Playbook

`system/diagnose` afegeix el pas `verify_visitor_view`; `purge_page_cache`
apunta a `site/cache-purge`; el pas del Builder explica `template/create` i
`preview_token`.

## Provat i no provat

Provat a dos webs de proves del servidor (WordPress 7.1.4 amb YOOtheme 5.0.53 i
Simple History 5.36; Joomla 6.2.0 amb YOOtheme 5.0.54), a més de les proves
locals de `npm test`:

- `site/public-fetch`: redireccions reals dins del web i cap a fora (es tallen
  sense demanar la destinació), 404, `cache_bust`, un `Host` amb port fals a
  Joomla.
- `site/cache-purge` a Joomla, amb la memòria cau de pàgina activada a mà: el
  visitant veu la còpia vella, `cache_bust` veu el canvi, i després de la purga
  el visitant també el veu.
- `template/create` als dos hosts, i un control positiu: activada a mà,
  YOOtheme aplica la plantilla al visitant.
- `template/render-check` amb pàgines, articles i plantilles amb context, i
  comparat amb `site/public-fetch`.
- Fragments: MirasAI ja hi arribava; ara està comprovat als dos hosts.

No provat: WP Rocket i JCH Optimize de debò (només funcions simulades o lectura
del codi), un servidor que no es pot cridar a si mateix (`loopback_failed`), una
resposta de més de 2 MB a Joomla, i la pantalla del registre d'accions de
Joomla (el missatge s'ha comprovat amb el fitxer d'idioma).

## Ajornat

L'avís de `props` desconegudes a les escriptures. La definició de l'element no
inclou els camps dels panells compartits (paral·laxi…) i, en un web real, donava
desenes de falsos positius. Detall a la proposta.
