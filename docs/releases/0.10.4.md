# MirasAI 0.10.4

Afegeix a WordPress tres rutes REST perquè Panopticon pugui comprovar un web al
voltant d'una actualització manual, també als webs sense SSH. No són eines MCP i
no canvien res del que fan els agents. Joomla i el router només pugen de versió.

## Logs PHP

`POST /wp-json/mirasai/v1/checks/logs` torna un cursor signat, i
`POST /wp-json/mirasai/v1/checks/logs/compare` compta les entrades noves des
d'aquell cursor. Mira `error_log`, `wp-admin/error_log`, `wp-content/debug.log` i
el fitxer que indica `error_log` a `php.ini`, sigui on sigui: en un compte cPanel,
PHP escriu fora de l'arrel en les peticions web, encara que la línia d'ordres
digui una altra cosa.

Només torna estats i recomptes, mai un missatge ni una ruta. Un error fatal nou és
una incidència. La resta només es compta, perquè un WordPress actiu registra
avisos en peticions normals. `covered: false` vol dir que PHP no escriu a cap
d'aquests fitxers.

## Memòria cau

`POST /wp-json/mirasai/v1/checks/cache/purge` buida WP Rocket, IONOS Performance i
la memòria d'objectes. Un `advanced-cache.php` amb contingut que aquestes rutes no
sàpiguen buidar surt com a `unsupported`, perquè la comprovació digui que pot haver
vist pàgines antigues.

Buidar la memòria cau pot alentir les primeres visites següents.

## Autenticació

Qualsevol usuari amb `manage_options`. El connector de Panopticon entra com a
administrador a les peticions REST amb el seu token, de manera que el panell no ha
de guardar cap altre secret.

## Provat i no provat

Provat amb actualitzacions reals en un web de prova, amb WP Rocket 3.24 sense
llicència: la cau plantada es buida, un error fatal escrit durant l'actualització
es detecta, i les peticions anònimes o amb token fals reben 401.

IONOS Performance només s'ha llegit al codi.
