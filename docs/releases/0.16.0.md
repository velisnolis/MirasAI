# MirasAI 0.16.0

Aquesta versió evita escriptures al web equivocat, conserva l'evidència d'un
canvi desat quan falla la verificació i afegeix lectures acotades i diagnosi de
bindings de YOOtheme. Inclou també els canvis de la 0.15.0, que estava preparada
al repositori però no s'havia publicat.

## Router local: destinació explícita i resultats d'escriptura

Amb diversos webs configurats, cal `site_id` per executar una eina d'escriptura,
encara que sigui un dry-run. També es requereix per a eines que no declaren de
manera fiable que són de lectura. Les lectures poden usar el web predeterminat;
un router amb un sol web o limitat amb `--site-id` conserva aquest comportament.

Un lot amb escriptures necessita `site_id` al nivell del lot abans d'executar
cap crida. Els lots són seqüencials, no transaccionals: els canvis anteriors
poden quedar desats si falla una crida posterior. Cal reconciliar-los abans de
repetir-los, sense reenviar tot el lot.

Style distingeix `write_state` de `verification_state`. Un canvi confirmat pel
host que falla en la lectura posterior retorna `saved` i `failed`, conservant
el resultat del host i l'ETag. Si es perd la resposta d'una escriptura, el
router indica `unknown`: un error de transport no demostra que no s'hagi desat.

Aquestes proteccions són del router. Els hosts continuen sense compilar LESS;
la compilació Style requereix el router local i el worker fixat per web.

## Hosts Joomla i WordPress: lectures acotades

`template/element-list`, en `mode=full`, accepta `subtree`, `max_depth`, `limit`
i `cursor`. El límit per defecte és 500 i el màxim 2000. `max_depth=0` retorna
només el node seleccionat. La resposta inclou `total`, `count`, `truncated` i
`next_cursor`. Per continuar, cal repetir els mateixos selectors i filtres.

Els cursors caduquen quan canvia el layout, la destinació o els filtres. Els
camins i l'ETag continuen referits al layout complet. Joomla conserva
`max_results` i la projecció `fields`. Els modes `outline` i `bindings_only`
conserven la seva forma i rebutgen els nous arguments de paginació.

**Migració:** els callers WordPress que esperaven tots els elements en una sola
resposta han de seguir `next_cursor` en layouts de més de 500 elements. Els
callers del router amb diversos webs han d'enviar `site_id` a les escriptures.

## Hosts: diagnosi del render dinàmic

`template/render-check` afegeix `binding_diagnostics`: identifica elements o
ancestres desactivats, context insuficient i propietats buides en totes les
instàncies renderitzades. `rendered_instances` compta còpies del node, no files
de base de dades. Si un node desapareix, la causa es marca com a desconeguda:
pot ser una consulta buida, una condició de visualització o manca de context.
`source_item_count` queda a null quan no es pot demostrar.

## Validació

Bateria completa `npm test` superada, incloses 106 proves del router. Dotze
comprovacions reals passen a cada laboratori: WordPress 7.1.4 amb YOOtheme
5.0.53 i Joomla 6.2.0 amb YOOtheme 5.0.56. Joomla confirma dues instàncies reals
d'un binding. Els fixtures continuen no publicats.

Aquestes proves invoquen el CMS i YOOtheme reals via CLI; no acrediten una
validació visual de navegador ni autenticació HTTP externa. Detall a la
[validació del 17 de novembre](../router-layout-validation-2026-11-17.md).
