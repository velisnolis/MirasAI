# MirasAI 0.10.1

This patch allows the first YOOtheme Style family to be assigned through the
local MirasAI router on Joomla and WordPress sites with no active family and
no stored Less variables or custom Less.

- `mirasai/style-update` can assign an installed family such as `fuse` to an
  unconfigured site. The host response identifies this as
  `style_assignment: initial`; existing-family updates report `active_family`.
- Joomla's final write gate now accepts a missing or empty `params.config`
  for a newly installed YOOtheme template. Previously the preview succeeded,
  but the real write failed with `stale_etag`. Malformed configuration and
  concurrent edits remain rejected.
- Switching between existing families remains unsupported. Stored overrides
  without a family are also rejected; no implicit reset or migration occurs.

The local router remains the only Style compiler. A host installation alone
cannot compile LESS. Use a pinned worker hash, preview/dry-run, a fresh `if_match`
and explicit confirmation for the write. Snapshot creation, CSS validation,
cache clearing and readback verification remain required. The private backup
directory outside Joomla's document root must be writable by the PHP user;
otherwise the host refuses the write with `snapshot_failed`.

## Validation

The full local suite passes, including WordPress and Joomla Style checks and
81 router tests. An isolated Joomla 5.4.5 / PHP 8.3.33 / YOOtheme 5.0.40 lab
reproduced the write-gate failure before the fix and passed afterward:
initial preview without writes, real assignment, snapshot creation, matching
readback ETag, and LTR/RTL CSS served over HTTP with matching SHA-256 hashes.
Stale ETags and family switches were rejected without changing the final state.

The complete Joomla 0.10.1 ZIP was also installed through Joomla's CLI installer;
the HTTP host reported 0.10.1 and the same integration checks passed again.

The opt-in integration runner is `docker/test-joomla-style-initial.mjs`;
[structured results](../qa/style-joomla-2026-09-19/evidence.json) record the run.
This patch has not been tested on a live WordPress installation or through
visual browser QA. It does not expand the supported family-switch policy.
